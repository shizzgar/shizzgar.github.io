# Forma — экспериментальная браузерная 3D-студия

Статический прототип: Qwen3.5-4B-3D-Coder в браузере через wllama/WebGPU, запрос с необязательной картинкой, изолированный предпросмотр сгенерированного HTML и его сохранение. Это независимая реализация интерфейса, код Pi Agent не копировался.

## Статус

**Эксперимент: сквозная работа модели, WebGPU и image input не подтверждена.** Для wllama файл модели должен быть разбит на части. Приложение ищет Q4 в стороннем зеркале `ReallyFloppyPenguin/Qwen3.5-4B-3D-Coder-GGUF-split`, которое может быть недоступно или содержать другой checkpoint; проверьте его содержимое и происхождение. Официальный vision-проектор берётся из репозитория ccore. Рантайм также должен поддерживать конкретную версию модели и проектор. При проблемах приложение сообщает об ошибке.

Нужны HTTPS, браузер с WebGPU и достаточно памяти. При первом запуске текстовой модели загружается около 2,7 ГБ, а при первом запросе с картинкой — ещё около 676 МБ для vision-проектора. Переход на работу с картинками требует повторной инициализации модели. Wllama использует локальный кэш, однако браузер может очистить его; работа в автономном режиме не гарантируется. Рабочее потребление памяти выше размера загрузки; на GitHub Pages многопоточный WASM, вероятно, будет недоступен без COOP/COEP. Скорость и требования не измерены. Код модели и веса загружаются с внешних сайтов; запросы и изображения обрабатываются локально, если модель успешно загрузится. CDN и хостинг весов должны быть доступны в браузере.

## Запуск

Разместите этот каталог на статическом HTTPS-хостинге. Если GitHub Pages настроен на корень ветки `master` в `shizzgar.github.io`, адрес после размещения будет `https://shizzgar.github.io/`. Настройка и доступность Pages здесь не проверены. Нажмите «Загрузить», дождитесь завершения, введите описание и при необходимости приложите JPG, PNG или WEBP.

Альтернативное зеркало можно подключить разработчику через аргумент `modelUrl` функции `loadModel` в `app.js`: нужен URL первого GGUF-шарда в нумерованном наборе. Скачивать единый 2,71-ГБ файл напрямую в wllama не следует из-за документированного лимита файла 2 ГБ.

Предпросмотр выполняет сгенерированный код в sandboxed iframe с ограничивающей CSP. Это снижает риски, но не гарантирует полной изоляции или защиты от зависания. Скачанный HTML — исходный код модели, и при открытии отдельно уже не имеет этих ограничений; проверяйте его перед запуском. Модель может ошибаться; экспорт GLB в прототипе не реализован.

## Если модель не скачивается

Кнопка «Проверить доступ» отдельно проверяет соединение с источниками файлов, движка и 3D-библиотеки из текущего браузера. Проверка не скачивает модель и не гарантирует работу каждого шарда, GPU или будущих запросов; ограничение CORS или запрет HEAD тоже может привести к ошибке проверки. Доступность адресов из России не подтверждена.

Раздел «Свои файлы модели» позволяет использовать заранее скачанные GGUF-шарды без обращения к Hugging Face за весами. Движок wllama и библиотека предпросмотра при этом по-прежнему загружаются с CDN; локальный импорт не является полностью автономным режимом. Выбранные файлы нужно выбрать заново после обновления страницы. Сайт проверяет заголовки и последовательность частей, но не происхождение и совместимость модели.

Для оригинального Q4 GGUF размером 2,71 ГБ необходимо предварительно разделить файл через утилиту `llama-gguf-split` из [llama.cpp](https://github.com/ggml-org/llama.cpp). Например, в каталоге с моделью:

```sh
llama-gguf-split --split-max-size 512M Qwen3.5-4B-3D-Coder-Q4_K_M.gguf Qwen3.5-4B-3D-Coder-Q4_K_M
```

В разделе «Свои файлы модели» выбери все полученные `.gguf` части; для картинки выбери также отдельный `mmproj-Qwen3.5-4B-BF16.gguf`. Нужен совместимый WebGPU и достаточно памяти. Реальная работа выбранных файлов не подтверждена в этой среде.

## Скачивание и докачка

Отдельные ссылки в разделе «Скачать файлы на компьютер» передают загрузку браузеру, который сохраняет файл на компьютер и сам управляет скачиванием. Возобновление этого скачивания зависит от браузера и сервера. Отдельную ссылку на компонент для картинок можно найти в разделе «Скачать файлы на компьютер».

При загрузке модели в Forma приложение может сохранять частично скачанные файлы в локальном хранилище браузера и продолжать их после обрыва. Для докачки внутри файла требуются поддержка OPFS с синхронным доступом, доступный сильный ETag и корректный ответ HTTP Range с необходимыми CORS-заголовками. Если эти условия не выполнены, текущая часть может скачаться заново. Завершённые части также могут использоваться из кэша; браузер вправе очистить хранилище. Вся эта функциональность не проверена с реальными весами или из РФ.

В разделе «Токен Hugging Face» можно необязательно ввести токен с правом чтения. Он передаётся через заголовок только для запросов к huggingface.co при загрузке модели в Forma, не хранится в приложении постоянно и удаляется при перезагрузке страницы. Прямая ссылка для скачивания на компьютер токен не использует. Токен не гарантирует более высокую скорость.

## Комплект одним архивом

Кнопка «Скачать комплект ZIP» в поддерживаемом браузере предлагает выбрать место сохранения и собирает один архив из всех найденных GGUF-частей и компонента mmproj. Она не режет исходный файл по байтам: нужны заранее подготовленные корректные части. Источник — сторонний split-репозиторий Hugging Face, доступность его файлов и скачивание из РФ не подтверждены. После скачивания распакуйте ZIP, затем выберите все части и, при необходимости, mmproj в разделе «С компьютера».

Архив пишется потоком без помещения всего файла в оперативную память. При поддержке OPFS данные могут сохраняться в браузерном кэше для повторной попытки; с архивом понадобится примерно вдвое больше свободного места, около 7 ГБ. Возобновление конкретного файла зависит от поддержки Range, ETag и CORS источником. Если браузер не поддерживает системный выбор файла (`showSaveFilePicker`), сборка ZIP недоступна. На время загрузки и упаковки держите вкладку открытой. Работа с реальными файлами и браузерами ещё не проверена.


## Агент и проверка сцены

Модель дообучена на [CCORE Three.js 3D Scenes](https://huggingface.co/datasets/ccore/ThreeJS-3D-Scenes): в нём 4 146 примеров с запросом, сгенерированными рассуждениями и полным ответом с HTML и JavaScript. В видимых примерах и в [карточке модели](https://huggingface.co/ccore/Qwen3.5-4B-3D-Coder) используется автономная сцена на Three.js core 0.160.0 с cdnjs, без дополнительных модулей; управление камерой реализуется внутри HTML. Forma запрашивает такой же тип результата. Это соответствие формату не доказывает улучшения качества на конкретном устройстве.

В датасете рендеры находятся отдельно в конфигурации `previews` и не входят в текстовые диалоги, поэтому по этому описанию нельзя утверждать, что модель обучалась на них как на входных изображениях. Автор модели отдельно описывает поддержку картинок с оригинальным vision-проектором и показывает пример. Надёжность оценки и исправления по кадру не установлена.

Запуск, сбор диагностик и повторные попытки организует внешняя браузерная оболочка. Описание датасета не подтверждает, что модель обучалась вызывать инструменты или исправлять сцену после выполнения: такие действия нельзя считать встроенным протоколом модели.

После запроса агент генерирует HTML, запускает его в изолированном iframe, проверяет ошибки выполнения и при необходимости пытается исправить код. Первичный цикл ограничен тремя попытками; предыдущее рабочее содержимое сохраняется, пока новый вариант не пройдёт проверку. В некоторых случаях после появления поздней ошибки агент может попытаться исправить её повторно. Если проблема связана с сетью, движком или пределом контекста, исправление не гарантировано.

Проверка охватывает сообщения JavaScript и загрузки ресурсов, а также признаки наличия canvas и рендеринга WebGL. Если загружен vision-компонент и доступен кадр, модель может дополнительно осмотреть сцену и референс. Такая визуальная оценка субъективна и приблизительна: она не гарантирует соответствие запросу, отсутствие поздних ошибок или качество 3D-геометрии. Проверка не заменяет просмотра результата человеком.

Исходящие подключения из проверяемой сцены ограничены, iframe изолирован от основного окна, но это не абсолютная защита: бесконечный синхронный цикл может зависнуть вместе с вкладкой и не всегда прерывается таймаутом. Скачанный HTML выполняется вне этой изоляции и требует самостоятельной проверки.

В текущей конфигурации Forma окно контекста составляет 8 192 токена, а лимит одного ответа — 4 096 токенов. Запрос, код предыдущей сцены, изображения, рассуждения и ответ конкурируют за ограниченный контекст; рассуждения также расходуют лимит вывода. Поэтому сложный или мультимодальный запрос может обрезать HTML или не поместиться, даже если модель поддерживает больший контекст. Автор модели описывает короткий тест vision с настройкой 65 536 токенов на локальном сервере; эти настройки не являются подтверждением работы или подходящими требованиями для браузера.

## Скорость и наблюдаемость

При первом запросе после загрузки модели, а при необходимости — компонента для изображений, приложение может автоматически сравнить две конфигурации запуска (`n_batch` 256 и 512, `n_ubatch` 128). Используется короткий фиксированный синтетический запрос, без передачи пользовательского текста или изображения; данные замеров остаются на устройстве. Если проверка прервана или результаты недоступны, приложение пытается восстановить предыдущие рабочие настройки. Повторная инициализация может занять время, и в ней повторно используются уже открытые файлы весов.

Скорость токенов и другие метрики показываются только по данным, которые вернул движок; потоковые фрагменты не приравниваются к токенам. Один короткий замер шумный и не гарантирует оптимальную скорость на будущих задачах. Поток ответа и отдельное поле рассуждений отображаются только в том виде, в котором их действительно отдаёт модель; не все сборки поддерживают отдельный поток рассуждений, а включённое мышление может работать медленнее и расходовать лимит вывода. Сквозной запуск реальной модели, точность визуальной оценки и ускорение на конкретных устройствах здесь не проверены.

Проверить логику извлечения HTML и повторных попыток без весов модели можно командой `node tests/agent-loop.mjs` (Node.js с поддержкой ES-модулей). Это тест оболочки с имитацией ответов, а не оценка модели на validation-части датасета.
